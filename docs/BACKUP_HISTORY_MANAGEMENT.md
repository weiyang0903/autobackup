# 备份历史与文件管理功能 (BACKUP_HISTORY_MANAGEMENT.md)

本文档详细说明备份历史记录追溯、安全流式下载、文件路径查看与磁盘文件清理联动的功能设计。

---

## 1. 功能概述

系统自动记录每一次手动或定时触发的备份执行结果，在页面提供清晰的审计表格。用户可以直接查看备份状态、耗时、文件体积、一键复制服务器物理路径、通过浏览器下载 `.sql` 备份文件到本地电脑，并支持安全删除历史与物理文件。

---

## 2. 交互与操作流程

1. **历史记录展示**：
   - 页面自动拉取 `/api/history`；
   - 列表展示：状态徽章（Success / Failed）、触发来源（Manual / 调度名称）、目标数据库名、生成文件名、文件体积、执行耗时及时间戳。
2. **复制文件路径**：
   - 点击文件名前方的复制图标，系统将该文件的绝对路径（如 `C:\xampp\htdocs\autobackup\backups\shop_2026-09-09.sql`）写入系统剪贴板，并显示绿勾反馈。
3. **一键浏览器下载**：
   - 针对状态为 Success 的记录，点击 "Download" 按钮；
   - 请求 `/api/backup/download?id=xxx`，后端校验文件存在性后以 `application/sql` 二进制流响应，并设置 `Content-Disposition: attachment` 唤起浏览器保存。
4. **安全删除操作**：
   - 点击操作列的删除图标；
   - 弹出确认对话框提示用户；
   - 确认后请求 `DELETE /api/history?id=xxx&deleteFile=true`，系统同步从 `history.json` 中移除元数据并清理磁盘物理文件。

---

## 3. 业务规则

1. **下载安全与防路径穿越**：
   - 下载接口仅接收合法的备份记录 `id`，从服务端存储的稳定元数据中读取真实文件路径；
   - 不允许客户端任意传参指定任意磁盘文件路径，杜绝路径穿越与任意文件下载漏洞。
2. **物理文件丢失容错**：
   - 若用户在磁盘上手动删除了 `.sql` 文件，点击下载时接口返回友好 404 提示："Backup file does not exist on disk"；
   - 仍允许用户在表格中直接删除该条失效记录。
3. **排序规则**：
   - 历史记录按时间倒序排列，最新生成的备份始终排在首位。

---

## 4. 错误处理机制

| 异常情况 | 触发原因 | 处理策略 |
| :--- | :--- | :--- |
| **下载不存在的文件** | 文件已被外部手动移动或删除 | 接口返回 404 状态与可读错误说明，不导致服务异常。 |
| **大文件下载中断** | 网络超时或客户端取消 | Node.js 流式传输机制自动释放文件句柄。 |
| **删除只读文件失败** | 磁盘文件被其他程序锁定 | 捕获文件删除错误并在日志中记录，保证元数据正常清理。 |
