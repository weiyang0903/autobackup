# 备份历史与文件管理功能 (BACKUP_HISTORY_MANAGEMENT.md)

本文档详细说明备份历史记录追溯、SQL 与备份文件夹一键 ZIP 流式打包下载、多层级物理路径定位、磁盘文件清理与空父目录自动清理联动的功能设计。

---

## 1. 功能概述

系统自动记录每一次手动或定时触发的备份执行结果，在页面提供清晰的审计表格。用户可以直接查看备份状态、耗时、总文件体积（包含 SQL 文件与复制的文件夹体积）、一键复制服务器物理路径、**一键将本次备份的所有 SQL 文件与文件夹完整打包为 `.zip` 压缩包下载到本地电脑**，并支持安全删除历史与磁盘文件，删除后自动清理变为空文件夹的父级目录。

---

## 2. 交互与操作流程

1. **历史记录展示**：
   - 页面自动拉取 `/api/history`；
   - 列表展示：状态徽章（Success / Failed）、触发来源（Manual / 调度名称）、目标数据库名与源文件夹名、相对路径、包含 SQL 与文件夹在内的总体积、执行耗时及时间戳。
2. **复制完整文件/目录路径**：
   - 点击路径前方的复制图标，系统将该次备份的完整绝对物理路径写入系统剪贴板，并显示绿勾反馈。
3. **一键 ZIP 打包下载**：
   - 针对状态为 Success 的记录，点击 **"Download ZIP"** 按钮；
   - 请求 `/api/backup/download?id=xxx`，后端基于 `archiver` 引擎（经 `serverExternalPackages` 原生加载）将本次时间目录下的所有 SQL 文件及备份的文件夹**流式压缩为 `.zip`**，边压缩边响应推送到浏览器；
   - 浏览器直接保存为结构完整的压缩包（如 `Daily_Core_backup_b_1788938.zip`）。
4. **安全删除与空目录清理**：
   - 点击操作列的删除图标；
   - 弹出确认对话框提示用户；
   - 确认后请求 `DELETE /api/history?id=xxx&deleteFile=true`：
     1. 从 `history.json` 中移除元数据记录；
     2. 递归删除该次备份在磁盘上生成的时间目录（包含 SQL 和所有复制的文件夹）；
     3. **自动向上递归清理空的父目录**（如日期目录 `2026-09-09` 和规则专属目录 `scheduleName_id`），直到遇到非空目录或到达备份根目录，确保磁盘无任何残留空文件夹。

---

## 3. 业务规则与流式下载安全

1. **流式压缩防内存溢出 (OOM Prevention)**：
   - 后端采用 Stream 管道（Pipe Stream）机制将压缩数据块直接写入 HTTP 响应体，不把整个大文件载入内存，保证对几百 MB 甚至数 GB 备份的极速稳定下载。
2. **下载安全与防路径穿越**：
   - 下载接口仅接收合法的备份记录 `id`，从服务端存储的稳定元数据中读取真实目录路径；
   - 不允许客户端任意传参指定任意磁盘文件路径，杜绝路径穿越漏洞。
3. **物理目录丢失容错**：
   - 若用户在磁盘上手动删除了该目录，点击下载时接口返回友好 404 提示："Backup directory does not exist on disk"。

---

## 4. 错误处理机制

| 异常情况 | 触发原因 | 处理策略 |
| :--- | :--- | :--- |
| **下载不存在的目录** | 目录已被外部手动移动或删除 | 接口返回 404 状态与可读错误说明，不导致服务异常。 |
| **大文件压缩中断** | 客户端网络断开或取消下载 | Node.js 流式传输机制自动捕获并安全销毁归档器与文件流句柄。 |
| **删除时目录只读/占用** | 个别文件正被其他程序独占打开 | 捕获删除错误并记录日志，保证元数据正常清理。 |
| **父目录非空** | 同一日期目录下还有其他时间的备份 | 仅清理当前时间目录，保留父级日期目录与其他兄弟备份。 |
