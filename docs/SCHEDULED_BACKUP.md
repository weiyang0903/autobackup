# 定时自动备份调度功能 (SCHEDULED_BACKUP.md)

本文档详细说明系统基于内置 Cron 引擎实现的周期性自动备份调度机制、规则配置、生命周期管理与并发控制。

---

## 1. 功能概述

系统提供全自动化的定时备份调度能力。用户无需配置复杂的操作系统级 Windows Task Scheduler，只需在网页中设置备份周期（如每小时、每日凌晨、每周日或自定义 Cron 表达式）、指定目标数据库和输出目录，后台服务即可常驻按时执行自动导出并记录审计日志。

---

## 2. 交互与配置流程

1. **新建调度规则**：
   - 点击 "New Schedule" 展开配置表单；
   - 输入调度名称（如 "Daily Production DB Backup"）；
   - 勾选该规则需要包含的数据库（支持多选）；
   - 选择快捷频率预设（Quick Preset）或手动输入标准 5 段式 Cron 表达式；
   - 可选指定专属输出目录（留空使用默认目录）；
   - 点击 "Save Schedule" 提交保存。
2. **规则持久化与调度器注册**：
   - 后端将规则写入 `data/schedules.json`；
   - 通过 `node-cron` 在 Node.js 事件循环中注册常驻定时任务。
3. **启停控制（Pause / Resume）**：
   - 用户可随时点击 "Pause" 临时暂停任务，或点击 "Resume" 恢复任务；
   - 状态变更即时同步给持久化文件及内存调度器实例。
4. **删除调度**：
   - 点击垃圾桶图标，确认后从 `schedules.json` 中移除，并销毁对应的 Cron 定时器。

---

## 3. 常用频率预设与 Cron 表达式对照表

| 预设名称 | Cron 表达式 | 说明 |
| :--- | :--- | :--- |
| **Every Hour** | `0 * * * *` | 每小时的第 0 分钟执行一次 |
| **Every 6 Hours** | `0 */6 * * *` | 每隔 6 小时执行一次 |
| **Daily at Midnight** | `0 0 * * *` | 每天凌晨 00:00 执行一次 |
| **Daily at 03:00 AM** | `0 3 * * *` | 每天凌晨 03:00 执行一次 |
| **Weekly (Sunday 02:00 AM)** | `0 2 * * 0` | 每周日凌晨 02:00 执行一次 |

---

## 4. 业务规则与稳定性保障

1. **常驻与恢复机制**：
   - 系统服务启动时（无论开发模式还是生产模式），调度器自动读取 `data/schedules.json` 并恢复所有处于 `enabled: true` 状态的任务；
2. **并发与重叠保护**：
   - 定时任务在触发时，调用统一的 `executeBackup` 核心库；
   - 每次生成带独立时间戳的文件，避免同名冲突；
3. **执行结果审计**：
   - 定时执行完毕后，自动在 `history.json` 中写入一条 `triggerType: "scheduled"` 的记录，并标记所关联的调度规则名称；
   - 成功后自动更新规则的 `lastRun` 字段。

---

## 5. 错误处理机制

| 异常情况 | 触发原因 | 处理策略 |
| :--- | :--- | :--- |
| **非法 Cron 表达式** | 输入了无效的格式（如字符超长、字段缺失） | 前端与后端均使用 `cron.validate()` 严格校验并拦截报错。 |
| **执行时 MySQL 临时离线** | 到达定时时间但 XAMPP MySQL 处于停止状态 | 任务执行捕获错误，记录状态为 `FAILED` 的历史记录（注明连接拒绝），不崩溃主服务进程。 |
| **目标路径已被删除** | 外部程序删除了目标备份目录 | 导出引擎自动递归重建该目录后继续写入。 |
