# 定时自动备份调度功能 (SCHEDULED_BACKUP.md)

本文档详细说明系统基于内置 Cron 引擎实现的可视化周期性自动备份调度机制、三档频率模式（Every Hour、Daily、Weekly）、多时间点选择、智能 Cron 编译、按日期自动分文件夹归类与并发控制。

---

## 1. 功能概述

系统提供全可视化的定时备份调度能力。用户无需学习和手动编写复杂的 Cron 表达式，直接通过图形界面选择备份频率（**Every Hour**、**Daily**、**Weekly**），自由添加一天中的一个或多个具体时间点（`HH:mm`），或自由多选周一至周日的任意天数。系统在后台自动将配置编译为精确的 Cron 任务，按时自动导出指定的 MySQL 数据库，并在目标目录下**按执行当天日期自动归入对应的 `YYYY-MM-DD` 子文件夹中**。

---

## 2. 如何使用 (How to Use)

### 2.1 新建调度规则
1. 打开控制台，在 **Automated Schedules** 区域点击 **"New Schedule"** 按钮展开配置面板；
2. **输入规则名称**（如 `Daily Core DB Backup`）；
3. **勾选目标数据库**（支持多选）；
4. **选择备份频率类型 (Backup Frequency)**：
   - **Every Hour（每小时）**：点击即生效，系统固定在每小时的整点（`XX:00`）执行备份，无需额外输入；
   - **Daily（每日）**：
     - 在时间框中选择时间（如 `09:00`），点击 **"Add Time"** 按钮添加到已选时间列表；
     - 可重复添加多个具体时间点（如 `09:00`、`14:30`、`22:00`）；点击时间标签上的 `✕` 可随时移除；
   - **Weekly（每周）**：
     - 在星期选择区（`Mon`、`Tue`、`Wed`、`Thu`、`Fri`、`Sat`、`Sun`）点击多选任意天数（例如同时选中周一、周三、周五）；
     - 同样支持在下方添加一个或多个具体时间点；
5. **指定输出目录（可选）**：留空使用 `.env` 中配置的默认目录，或填入自定义绝对路径（如 `D:\mysql_backups`）；
6. 点击 **"Save Schedule"** 提交保存，后台即刻启动监听。

### 2.2 启停与删除控制
- **暂停 (Pause)**：点击列表项右侧的 "Pause" 按钮，任务进入暂停状态，不注销规则但不会触发执行；
- **恢复 (Resume)**：点击 "Resume" 按钮重新激活任务；
- **删除 (Delete)**：点击垃圾桶图标，在弹出确认框后从系统中永久移除该规则并销毁后台定时器。

```mermaid

    A[用户在界面配置规则: Name / DBs / 频率 / 时间 / 星期] --> B[前端表单校验: 必填项 / 时间格式 / 至少1天1时间]

    E -->|Daily: 09:00, 14:30| F2["0 9 * * *" & "30 14 * * *"]

    F1 & F2 & F3 --> G[写入 data/schedules.json 持久化]
```

## 4. 智能 Cron 编译规则与原理

为了避免传统的单条 Cron 表达式在不同分钟（如 `09:00` 与 `14:30`）合并时发生笛卡尔积交叉误触发，系统采用**单规则多 Cron 编译算法**：

| 频率模式 | 前端选择配置 | 底层编译生成的 Cron 表达式数组 | 执行行为说明 |
| :--- | :--- | :--- | :--- |
| **Every Hour** | 选中 Every Hour | `["0 * * * *"]` | 每小时的第 00 分钟执行一次 |
| **Daily** | `times: ["09:00", "18:30"]` | `["0 9 * * *", "30 18 * * *"]` | 分别在每天 09:00 和 18:30 各精准触发一次 |
| **Weekly** | `weekDays: [1, 3, 5]`<br>`times: ["02:00", "22:15"]` | `["0 2 * * 1,3,5", "15 22 * * 1,3,5"]` | 每周一、三、五的 02:00 和 22:15 各精准触发一次 |

## 5. 输入校验规则 (Validation)

1. **规则名称**：必填，不能为空字符串；
2. **数据库列表**：必选，至少包含 1 个合法的数据库名称（正则 `^[a-zA-Z0-9_\-$]+$`）；
3. **Daily 模式**：
   - 必须包含至少 1 个有效的时间点；
   - 时间必须符合标准 24 小时制 `HH:mm` 格式（`00:00` ~ `23:59`）；
   - 前端与后端自动过滤重复的时间点；
4. **Weekly 模式**：
   - 必须选择至少 1 个星期天数（`0-6`）；
   - 必须包含至少 1 个有效的时间点；
5. **保存路径与日期子目录**：自动校验绝对/相对路径可写权限，系统按执行日期自动建立并追加写入 `YYYY-MM-DD` 目录；
6. **服务端二次编译校验**：编译生成的每一条 Cron 表达式均须通过 `cron.validate()` 验证。

## 6. 错误处理机制 (Error Handling)

| 异常情况 | 触发原因 | 处理策略 |
| :--- | :--- | :--- |
| **未添加任何时间点** | 在 Daily/Weekly 模式下清空了所有时间便尝试提交 | 前端拦截并红框提示："Please add at least one backup time"；服务端返回 400 状态。 |
| **未勾选任何星期** | Weekly 模式下取消了所有星期的勾选 | 前端拦截提示："Please select at least one day of the week"；服务端返回 400 状态。 |
| **添加重复时间** | 用户重复点击已存在的时间（如已添加 09:00） | 前端提示 "Time 09:00 is already added"，不重复压入数组。 |
| **执行时 MySQL 临时离线** | 定时器到达但 XAMPP MySQL 处于关停状态 | 调度器捕获错误，记录状态为 `FAILED` 的历史记录（注明连接被拒绝），主服务常驻进程不崩溃。 |
| **输出目录被外部删除** | 定时触发前目标目录被其他软件清理 | 导出引擎自动递归重新创建该根目录及当天日期子目录后再行导出。 |
